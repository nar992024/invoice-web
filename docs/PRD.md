# 노션 연동 견적서 열람 서비스 MVP PRD

## 1. 핵심 정보

**목적**: 운영자가 노션에 입력한 견적서를 클라이언트가 링크 하나로 웹에서 확인하고 PDF로 내려받게 한다.
**사용자**: 노션에서만 견적서를 작성·발행하는 운영자 1명, 전달받은 링크로 열람만 하는 클라이언트(회원가입·로그인 없음).

---

## 2. 사용자 여정

### 2-1. 운영자 (노션에서만 수행, 별도 관리자 화면 없음)

```
1. 노션 `견적서` 데이터베이스에 행 추가 (상태: 작성중)
   ↓ `견적 항목` 데이터베이스에 항목 행 추가 후 `소속 견적서`로 연결
2. 상태를 `발행`으로 변경
   ↓ `공개 링크` 속성 값을 복사
3. 링크를 클라이언트에게 직접 전달 (전달 수단은 운영자가 선택, 서비스는 발송하지 않음)
4. 수정이 필요하면 노션에서 수정 → 다음 열람 또는 PDF 요청부터 반영
   취소하려면 상태를 `취소`로 변경 → 다음 요청부터 안내 화면으로 바뀜
   상태를 다시 `발행`으로 바꾸면 같은 링크가 다시 열림 (공개 여부는 현재 상태로만 결정)
```

### 2-2. 클라이언트

```
1. 전달받은 링크 클릭
   ↓ 링크의 페이지 ID 형식 검사
   [형식 아님] → 접근 불가 안내 페이지 (노션 호출 안 함)
   ↓ 노션에서 견적서 조회
   [일시 장애] → 일시 오류 안내 페이지 ── [다시 시도] → 1단계 재실행
   [페이지 없음 / 접근 불가 / 휴지통·보관 / 다른 데이터 소스 / 상태가 발행이 아님]
                                   → 접근 불가 안내 페이지 (원인 구분 없이 같은 화면)
   [상태 발행] ↓ 견적 항목 조회 및 검증
   [일시 장애] → 일시 오류 안내 페이지
   [항목 값 오류 / 노션 속성 구조 오류 / 항목 조회 설정 오류]
                                   → 표시 불가 안내 페이지 (서버 로그 기록)
   [정상]
2. 견적서 페이지 (유효기간이 지났으면 `유효기간 만료` 표시, 열람은 계속 가능)
   ↓ [PDF 다운로드] 클릭, 서버가 같은 판정을 다시 수행
   [정상] → PDF 파일 저장
   [판정 실패] → 견적서 페이지로 다시 이동 → 판정 결과에 맞는 안내 페이지
3. 완료 (다른 이동 없음)
```

### 3-1. MVP 핵심 기능

| -------- | ---------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------- | ------------- |
| **F001** | 노션 견적서 조회 | 요청마다 노션 `견적서` 페이지 1건과 소속 `견적 항목` 전체를 읽어 견적서 데이터로 변환. 데이터 캐시를 쓰지 않음                                                                                                                                                                                        | 노션이 유일한 데이터 원천이며 취소가 바로 반영되어야 함 | 견적서 페이지 |
| **F002** | 견적서 웹 열람   | 발행자 정보, 견적 기본 정보, 항목 표, 금액 요약, 입금 계좌, 비고를 한 화면에 표시. 항목 0개이면 빈 표 문구 표시                                                                                                                                                                                       | 클라이언트의 핵심 목적                                  | 견적서 페이지 |
| **F003** | 금액 계산        | 항목 금액 = 수량 × 단가(원 미만 절사), 공급가액 = 항목 금액 합, 부가세 = 공급가액 × 10%(원 미만 절사), 합계 = 공급가액 + 부가세. 부가세 미적용이면 부가세 행 대신 `부가세 미적용` 표시, 합계 = 공급가액. 노션 숫자를 10진 문자열로 바꿔 BigInt 정수 연산으로 계산. 화면과 PDF가 같은 계산 함수를 사용 | 금액 정확성과 화면·PDF 일치                             | 견적서 페이지 |
| **F004** | PDF 다운로드     | 서버에서 A4 PDF 생성. 여러 페이지, 표 헤더 반복, 페이지 번호, Noto Sans KR 임베드, 파일명 `견적서_{견적번호}_{클라이언트명}.pdf`                                                                                                                                                                      | 클라이언트 보관·제출용                                  | 견적서 페이지 |

**F013 표시 불가 조건**

- 항목명이 비어 있음
- 수량이 비어 있거나 0 이하임
- 단가가 비어 있거나 음수임
- 수량이나 단가를 10진 문자열로 바꿨을 때 지수 표기가 됨
- 합계가 15자리(999,999,999,999,999원)를 넘음
- `상태`를 제외한 필수 속성의 키가 없거나 타입이 6절 표와 다름(값이 비어 있는 경우와 구분)
- 항목 쿼리에서 설정 오류가 발생함(6-5 오류 분류)

### 3-3. MVP 제외

전자서명, 승인/거절, 결제, 이메일 발송, 관리자 대시보드, 견적 이력 관리, 다국어, 다중 통화, 세금계산서 발행, 앱 내 견적서 편집, 할인 항목(음수 단가), 링크 비밀번호, 회원가입/로그인, 랜딩 화면.

**PDF 구성(F004)**

- A4 세로. 첫 페이지 상단에 발행자 정보와 견적서 제목·기본 정보, 이어서 항목 표.
- 표 헤더(순번, 항목명, 수량, 단가, 금액)는 표가 이어지는 모든 페이지 상단에 반복. 항목 한 행은 페이지 사이에서 잘리지 않고 다음 페이지로 이동.
- 마지막 항목 뒤에 금액 요약, 입금 계좌, 비고. 금액 요약만 새 페이지로 넘어갈 때 행 없는 표 헤더가 나타나지 않게 함.
- 모든 페이지 하단에 `현재 페이지 / 전체 페이지` 표시. 유효기간이 지난 견적서는 PDF에도 `유효기간 만료` 표시.
- 폰트는 Noto Sans KR 정적 TTF 400·700 임베드(가변 폰트와 WOFF 사용 안 함).
- 공백 없는 긴 한글이 표 밖으로 넘치지 않도록 문자 단위 줄바꿈 콜백을 등록: `Font.registerHyphenationCallback((word) => [...word].flatMap((char) => [char, '']))`. 이 설정에서는 숫자와 영단어 중간도 줄이 바뀔 수 있음.

**PDF 응답(F004)**

- 성공 응답 헤더: `Content-Type: application/pdf`, `Cache-Control: private, no-store`, `Content-Disposition: attachment; filename="quote.pdf"; filename*=UTF-8''<인코딩한 파일명>`.
- 파일명 인코딩은 RFC 5987을 따르며 `'()*` 문자도 인코딩.
- 파일명 가공: 금지 문자(`\ / : * ? " < > |`, 제어문자, 줄바꿈) 제거, 앞뒤 공백 제거, 연속 공백 1개로 축소, 견적번호·클라이언트명이 비면 `미지정`으로 대체, 확장자를 제외하고 100자로 자름.

## 6. 데이터 모델

데이터는 노션 데이터베이스 2개와 서버 설정값으로만 구성한다. 별도 DB는 없다. 노션 속성 이름은 아래 표와 글자 하나까지 같아야 한다. 노션이 새 데이터베이스에 자동 생성하는 기본 제목 속성(`이름`)은 표의 이름(`제목`, `항목명`)으로 바꾼다.

### 6-1. 노션 데이터베이스 `견적서`

| 속성 이름    | 노션 속성 타입(API 타입) | 필수 | 입력 규칙                                                                     | 화면·PDF 표시 위치                  |
| ------------ | ------------------------ | ---- | ----------------------------------------------------------------------------- | ----------------------------------- |
| 제목         | 제목 (title)             | 필수 | 견적서 제목                                                                   | 견적서 제목                         |
| 견적번호     | 텍스트 (rich_text)       | 필수 | 운영자가 직접 입력. 중복 방지는 운영자 책임                                   | 견적번호, 파일명                    |
| 클라이언트명 | 텍스트 (rich_text)       | 필수 | 수신 업체·개인명                                                              | 클라이언트명, 파일명                |
| 담당자       | 텍스트 (rich_text)       | 필수 | 클라이언트 측 담당자명. 값은 비워도 됨                                        | 담당자                              |
| 발행일       | 날짜 (date)              | 필수 | 날짜만 입력. `start`의 앞 10자만 사용, `end`는 무시                           | 발행일                              |
| 유효기간     | 날짜 (date)              | 필수 | 이 날짜 당일까지 유효. 값은 비워도 됨. `start`의 앞 10자만 사용, `end`는 무시 | 유효기간, 만료 판정                 |
| 상태         | 선택 (select)            | 필수 | 옵션 3개: `작성중`, `발행`, `취소` (이름 정확히 일치). 기본값은 `작성중` 권장 | 공개 여부 판정(화면에는 표시 안 함) |
| 부가세 적용  | 체크박스 (checkbox)      | 필수 | 체크하면 부가세 10% 적용                                                      | 부가세 행 또는 `부가세 미적용`      |
| 비고         | 텍스트 (rich_text)       | 필수 | 자유 문구. 값은 비워도 됨                                                     | 비고                                |
| 공개 링크    | 수식 (formula)           | 필수 | `"서비스 주소/견적서 페이지 경로/" + id()`. 운영자가 이 값을 복사해 전달      | 표시 안 함(운영자 전용)             |

"필수"는 이 속성이 데이터베이스에 반드시 있어야 한다는 뜻이다. 필수 속성의 키가 없거나 타입이 다르면 F013에 따라 표시 불가로 처리하고 스키마 오류를 기록한다. 단, `상태`를 읽을 수 없으면 접근 불가로 처리한다. 값이 비어 있으면 `-`로 표시한다.

### 6-5. 연동 제약

- **연결 설정**: 내부 연결(Internal connection)에 `Read content` 권한만 부여하고 `견적서`·`견적 항목` 두 원본 데이터베이스를 모두 공유한다.
- **토큰 서버 전용**: `NOTION_API_KEY`는 서버 코드에서만 읽고 브라우저로 내려보내지 않는다.
- **API 버전**: SDK 클라이언트에 `notionVersion: '2026-03-11'`을 명시한다. 생략하면 `2025-09-03`으로 동작한다.
- **조회 단위**: 견적서는 페이지 ID로 1건 조회하고, 항목은 `견적 항목` 데이터 소스에 `소속 견적서` 관계가 해당 페이지 ID를 포함하는 조건으로 쿼리한다. `parent.data_source_id`와 설정값은 정규화해 비교한다.
- **항목 읽기**: 페이지 응답의 relation은 최대 25개만 포함하므로 읽지 않는다. 쿼리는 `has_more`가 거짓이 될 때까지 `next_cursor`로 끝까지 읽는다. `request_status`가 `incomplete`이거나 부분 객체가 있으면 항목을 걸러내지 않고 오류로 처리한다. `in_trash` 또는 `is_archived`가 참인 행은 제외한다.
- **재시도**: 재시도는 SDK에 맡기고 앱에 별도 재시도 루프를 두지 않는다. 설정은 `retry: { maxRetries: 3, maxRetryDelayMs: 5000 }`, `timeoutMs: 10000`이다. 사용자가 기다리는 화면이므로 `Retry-After`가 5초를 넘어도 5초 후 재시도하는 절충을 받아들인다.
- **SDK가 재시도하지 않는 경우**: 쿼리의 500·503, 모든 요청의 502·504, 타임아웃, 네트워크 오류는 바로 일시 오류 화면으로 보내고 사용자의 [다시 시도]로 복구한다.
- **캐시 없음**: 페이지와 PDF 요청마다 노션을 조회한다. `unstable_cache`, fetch 데이터 캐시, 정적 생성은 쓰지 않는다. 기한이 지난 값을 먼저 돌려주는 방식으로는 취소한 견적서가 노출될 수 있기 때문이다. 페이지 응답에도 `Cache-Control: private, no-store`를 지정한다.
- **화면과 PDF의 시점**: 각 요청의 조회 시점이 다르므로 화면을 연 뒤 노션을 수정하면 PDF에는 최신 값이 들어간다.
- **텍스트 읽기**: title·rich_text는 조각의 `plain_text`를 순서대로 이어 붙여 읽는다.
- **파일 속성 없음**: MVP 노션 속성에 파일이 없으므로 노션 파일 URL 만료 문제는 없다.

**노션 오류 분류**

| 호출        | 응답                                    | 처리                       |
| ----------- | --------------------------------------- | -------------------------- |
| 페이지 조회 | 400, 404                                | 접근 불가                  |
| 페이지 조회 | 401, 403                                | 접근 불가 + 설정 오류 로그 |
| 항목 쿼리   | 400, 401, 403, 404                      | 표시 불가 + 설정 오류 로그 |
| 모든 호출   | 409, 429, 5xx, 네트워크 오류, 타임아웃  | 일시 오류                  |
| 응답 처리   | `request_status: incomplete`, 부분 객체 | 일시 오류                  |

### 8-1. 구현 중 확인할 사항

**첫 구현 단계**

1. `next build --turbopack`과 PDF 응답이 실제로 동작하는지 확인한다. 실패하면 `--turbopack`을 빼고 원인을 기록한다.
2. Next.js 15.5.28과 React 19.1.10이 최신 보안 권고를 모두 반영했는지 확인한다. React 19.1.10의 후속 CVE 수정 포함 여부는 확인하지 못했다.
3. Noto Sans KR 정적 TTF의 공식 배포 경로를 정한다. 검증에 쓴 파일은 Google Fonts CSS API로 받은 것으로 공식 배포 경로가 아니다.

**실제 노션 연결로 확인**

4. 휴지통 페이지 조회 응답(200 또는 404)과 쿼리 결과 포함 여부
5. `is_archived`와 `in_trash`의 실제 차이
6. 시각이 포함된 `date.start`의 오프셋 형식. 앞 10자를 쓸 때 한국 날짜와 하루 어긋나는지 확인한다.
7. `created_time` 정밀도
8. `견적 항목` 또는 `견적서`를 공유하지 않았을 때의 쿼리 응답. 오류 없이 0건을 반환하면 공유 누락이 0원 견적서로 보일 수 있으므로, 배포 후 샘플 견적서로 항목 수를 확인한다.
9. 형식은 맞지만 없는 페이지 ID의 응답 코드(400 또는 404)
10. `공개 링크` 수식의 `id()` 반환 형식. F010이 하이픈 유무를 모두 허용하므로 동작에는 영향이 없다. 수식에 넣을 경로는 구현 시 확정한다.

**배포 환경**

11. Vercel 함수 실행 시간 제한. 현재 재시도 설정의 호출당 최악 시간은 약 55초(타임아웃 10초 × 4회 + 대기 15초)이므로, 제한보다 길면 값을 줄인다.
12. 배포 환경의 PDF 렌더링 시간과 메모리. 로컬 측정값은 5페이지 기준 약 1초, 약 190MB이다.
13. 캐시 없이 요청마다 조회할 때의 체감 속도. 느리면 시간 구간 키 방식의 캐시를 실행 검증한 뒤 도입한다.

### 8-2. 이 PRD가 세운 가정 (이의 없으면 그대로 구현)

1. 판정 순서는 공개 조건(F011) 먼저, 데이터 검증(F013) 나중이다. 따라서 작성중·취소 견적서는 항목에 오류가 있어도 접근 불가 안내만 보인다.
2. 항목 금액을 먼저 원 미만 절사한 뒤 합산한다.
3. 수량과 단가의 소수 입력을 허용한다.
4. 견적서 텍스트 속성이 비어 있으면 `-`로 표시한다.
5. 발행일이 미래이거나 유효기간이 발행일보다 앞서는 경우는 검증하지 않고 입력값 그대로 표시한다.
6. 색인 차단은 meta와 응답 헤더로만 처리하고 `robots.txt`는 두지 않는다.
7. 서비스 주소(도메인)는 배포 후 확정되며, 운영자가 `공개 링크` 수식에 한 번 입력한다.
8. 부가세는 10%, 원 미만 절사로 고정한다.
